# IDD-0006.spec-about-and-application-update

## Intent

WhisperDrop exposes its release version through an About menu, checks the latest stable GitHub Release, and can update and restart a supported Homebrew installation on macOS without introducing a second distribution channel.

## Related Specifications

- IDD-0005 — Release distribution

## Behavior

- The primary navigation exposes an application overflow menu with `About WhisperDrop…`.
- About opens immediately and displays the current application version before network checking finishes.
- Latest stable version is read from `GET /repos/DimonSmart/WhisperDrop/releases/latest`.
- Release versions are compared numerically as `MAJOR.MINOR.PATCH`, not lexically.
- When a newer release exists, About shows its version and provides `Open release page`.
- Network timeout, HTTP error, invalid release metadata, or browser-launch failure is contained within About and does not disrupt transcription.
- Windows and unsupported macOS installations support version display, update check, and release-page navigation but not automatic installation.
- `Update now` is shown only when the macOS updater verifies:
  - the current process runs from `/Applications/WhisperDrop.app/Contents/MacOS/`;
  - Homebrew is available;
  - `dimonsmart/whisperdrop/whisperdrop` is installed.
- Manual ZIP, debug, custom-path, or non-Homebrew installations never receive an automatic update action.

## macOS Homebrew Update Contract

- Before changing the installed package, the updater runs `brew update`.
- It then reads `brew info --cask --json=v2 dimonsmart/whisperdrop/whisperdrop` and confirms that Homebrew has published at least the expected GitHub Release version.
- If GitHub Release is newer than the Cask, no downgrade/stale installation is attempted; the user is told to retry after publication catches up.
- Package modification uses only:
  `brew upgrade --cask --no-quit --appdir=/Applications dimonsmart/whisperdrop/whisperdrop`.
- Cancellation is supported before package modification. Once `brew upgrade` starts, the updater does not cancel or kill the Homebrew process.
- After upgrade, `/Applications/WhisperDrop.app/Contents/Info.plist` must report `CFBundleShortVersionString >= expectedVersion`.
- The updater removes `com.apple.quarantine` using `/usr/bin/xattr` and verifies that quarantine is absent before relaunch.
- Relaunch uses `/usr/bin/open -n /Applications/WhisperDrop.app`.
- The old application window closes only after successful upgrade verification, quarantine handling, and relaunch.
- Any failure leaves the current WhisperDrop process open.

## Durable Architecture And Constraints

- About UI does not implement HTTP, Homebrew discovery, command execution, version parsing, or system-browser behavior directly.
- GitHub release checking, process execution, update environment, installer, version provider, and URI launching are separate service responsibilities.
- Homebrew commands are launched directly with argument lists, never through a shell command string.
- GitHub update check is unauthenticated and bounded by a short timeout.
- GitHub Release plus this repository's Homebrew Cask remain the only update source.
- A future Windows installer/updater can implement the same installer abstraction without changing About behavior.

## Acceptance Criteria

- About always shows the current version.
- About reports checking, up-to-date, update-available, or unavailable state without blocking opening the dialog.
- A newer release can be opened in the system browser.
- A supported Homebrew macOS installation receives `Update now`.
- Unsupported installations do not expose automatic installation.
- Publication lag, Homebrew errors, invalid metadata, quarantine failure, and relaunch failure never terminate the current process.
- Successful macOS update verifies the new version and launches the updated application before closing the old window.

## Verification

- Unit tests cover semantic version parsing/comparison and GitHub release response behavior.
- Unit tests cover Homebrew installation detection, targeted upgrade arguments, publication lag, quarantine failure, and relaunch sequence.
- Release/Homebrew workflows provide the artifacts and Cask metadata consumed by the updater.
