# IDD-0007.spec-ai-transcript-post-processing

## Intent

WhisperDrop may optionally improve an already completed local Whisper transcript with an LLM while preserving the original recognition result as immutable session data.

## Related Specifications

- IDD-0001 — Local desktop transcription and privacy boundaries
- IDD-0002 — Transcription workspace
- IDD-0003 — Model settings and availability

## Behavior

- For correction, the model receives the detected language, original segment text, segment start and end times, and all available segment confidence values. Adjacent original segments may be supplied as read-only context.
- The model uses language, context, timing, and confidence signals to reconsider likely recognition errors, including short words split or merged at word boundaries and misplaced sentence boundaries. It checks that corrections preserve natural grammar and meaning, and preserves wording when no well-supported correction is available. The correction model receives text and recognition metadata, not audio.

- AI post-processing is disabled by default and never starts merely because the application was installed, upgraded, or launched.
- Whisper recognition remains local. AI post-processing starts only when explicitly enabled for transcription or explicitly invoked for an existing raw transcript.
- The default AI provider preset is Ollama at `http://localhost:11434/v1/`.
- The integration uses Microsoft Agent Framework over an OpenAI-compatible Chat Completions client. Ollama is a configuration preset, not a separate application transport.
- Custom OpenAI-compatible endpoints are supported. A non-loopback endpoint is clearly identified as a destination to which transcript text will be sent.
- API keys are session-only in the first version and are not persisted by the JSON settings store.
- AI settings are captured as an immutable snapshot for an enhancement operation. A batch uses one snapshot for its complete AI phase.
- The complete raw `RecognitionResult`, including ordered segments, timestamps, and probability metadata, remains unchanged after AI processing.
- A successful enhancement is stored separately as `ProcessedTranscript`. `EffectiveTranscript` is the processed text when present and otherwise the raw transcript.
- A repeated enhancement always starts from the original raw `RecognitionResult`, never from a previous processed version.
- AI failure or cancellation never converts successful Whisper recognition into a recognition error. The raw transcript remains available and copyable.
- `Copy` uses the effective transcript. `Copy raw` is available after a processed version exists. Preview and `Copy all` also use effective transcripts.
- Long transcripts are divided deterministically on recognition-segment boundaries. Small adjacent read-only context may be supplied but is never returned as output.
- Each chunk is processed statelessly. No agent conversation history is shared across chunks, files, or repeated enhancement runs.
- The LLM returns typed corrected segments keyed by the original segment IDs. WhisperDrop validates IDs, completeness, duplicates and text before accepting a chunk.
- Paragraph boundaries are represented explicitly and deterministic application code merges all corrected segments into the processed transcript.
- Transcript content is untrusted source data, not model instruction. Application guardrails require preservation of meaning and prohibit summarizing, translating, answering transcript questions, omitting content, or inventing facts.
- Session transcripts, chunks, prompts, responses and agent history are never persisted to disk and are not written to logs.
- `Test connection` uses the same client/agent creation path as production enhancement and verifies a structured Chat Completions response.

## Batch Semantics

When AI post-processing is enabled, `Transcribe all` has two sequential phases:

1. Whisper transcribes queued files in visual order while reusing the loaded Whisper model.
2. The Whisper recognition model is unloaded.
3. AI enhancement processes each successfully recognized file in visual order.

An AI failure for one file does not prevent enhancement of later successfully recognized files.

## Product-Significant Architecture And Constraints

- `WhisperRecognitionService` has no dependency on Agent Framework, OpenAI, Ollama, or AI post-processing settings.
- `TranscriptEnhancementService` owns chunking, request orchestration, validation, deterministic merge, progress, and cancellation.
- Model-client/agent construction is behind `ITranscriptEnhancementAgentFactory`.
- The OpenAI-compatible adapter uses Chat Completions rather than the Responses API for the first version.
- Provider-specific model installation and model-management UI are outside this intent.

## Non-Goals

Summarization, meeting notes, action-item extraction, translation through the LLM, transcript Q&A, RAG, MCP, vector search, multi-agent workflows, speaker diarization, persistent transcript history, persistent API-key storage, automatic Ollama installation, and automatic LLM downloads are not part of AI transcript correction.

## Acceptance Criteria

- AI correction receives detected language and every available segment-level timing and confidence value alongside the original text.
- Low-confidence or contextually implausible wording is reconsidered using nearby original text, word boundaries, and sentence flow; unsupported content is not invented.

- With AI disabled, ordinary Whisper transcription behaves as before and makes no AI request.
- WhisperDrop runs normally when no AI server is installed or reachable.
- A user can configure Ollama or another OpenAI-compatible endpoint/model and test structured-output compatibility.
- Recognition segments preserve source order, original-file timestamps, and Whisper probability metadata.
- Successful AI processing produces a separate processed transcript without changing the raw recognition result.
- AI failure leaves recognition completed and the raw transcript copyable.
- Re-running AI uses the raw recognition result and does not re-run Whisper.
- Large transcripts are processed in validated segment-based chunks with deterministic merge.
- Batch recognition finishes and unloads the Whisper model before the AI phase begins.
- No API key or transcript content is persisted in ordinary settings/session storage.
