# IDD-0004.spec-compact-visual-system

## Intent

ParakeetDrop presents its transcription workflow as a compact, modern dark desktop tool. The visual system makes the file queue the primary working surface and the external file drag-and-drop target, keeps recognition controls compact, and uses shared semantic resources instead of screen-local styling.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0002 — Transcription workspace
- IDD-0003 — Model settings and availability
- IDD-0007 — Optional AI transcript post-processing

## Behavior

- The application uses a dark desktop presentation with a small set of reusable color, spacing, radius, typography, surface, button, and status resources.
- The native window title identifies the application as ParakeetDrop. The page content does not repeat a large ParakeetDrop heading solely to compensate for an incorrect or generic title bar.
- The application icon and About presentation use the ParakeetDrop identity.
- The main window is a single Transcribe workspace with no task/navigation tabs. Configuration is accessed through a Settings command in the application menu, opening a dedicated window with left navigation and a right settings pane.
- The page does not carry a persistent explanatory privacy sentence above navigation. Local-only behavior is product behavior rather than repeated decorative copy.
- The supported Parakeet Ultra Q8_0 model is identified in the Transcribe workspace, where its installed state and an unavailable-model Download action are clear. Processing device and CPU threads reside in Settings > Recognition.
- Model availability and download progress/errors use restrained status styling and do not reserve space for unavailable model choices.
- The file queue is the primary working surface and also serves as the external file drag-and-drop target. There is no separate drop panel above the queue.
- When the queue is empty, the queue workspace shows a compact drop hint and a generic audio/video-format description. It does not duplicate the Add files action or hard-code a partial extension list.
- The Files toolbar shows the current file count, Add files, Copy all as a lower-priority action, and Transcribe all as the primary action.
- Each queued file is a compact row/card that prioritizes file name, then path and metadata, and presents Pending, Transcribing, Completed, and Error with distinct semantic status styling.
- Selection in the file queue is indicated by an accent outline following the card's rounded contour, not by a rectangular selection fill or a bottom stripe. Row content and progress remain unobscured.
- Active transcription progress is shown inside the file row. Preview and error text are bounded so one row does not unnecessarily dominate the queue.
- Row-level Transcribe, Copy, and Remove actions have different visual weight while preserving their existing behavior. Icon-only actions must reserve enough layout space that their glyphs are not clipped at normal desktop sizes.
- Settings > Models & storage presents model management without unnecessary nested cards. It contains the models-folder control, installed-model list with actual sizes, total downloaded size, and model download/deletion actions.
- Downloading a model is presented in a modal flow so model choice and download progress do not create a permanent status block in the Models workspace.
- Individual and delete-all model actions use destructive visual treatment and confirmation.
- The Transcribe layout adapts to reduced window width without overlapping controls and gives the file queue priority when vertical space is limited.
- The initial visual target is dark. Shared resources must keep a later light-theme implementation possible without rewriting every screen.

## Product-Significant Architecture And Constraints

- Product state remains independent of visual state. View-model objects expose product concepts such as status, progress, capabilities, installed models, sizes, and selected navigation index; brushes, icons, visibility mapping, and other presentation decisions remain in the UI layer.
- Visual resources remain inside the existing application project and do not introduce a separate design-system or control-framework project.
- The presentation remains compatible with the Uno/Skia Desktop foundation used for Windows and macOS.

## Non-Goals

- Pixel-perfect reproduction of a reference image, a theme editor, selectable accent colors, a user density setting, a separate UI framework, and a new light theme are outside this change.

## Acceptance Criteria

- The native title bar shows ParakeetDrop, and the page body does not redundantly repeat the application name as a large heading.
- The interface is compact and does not use the default browser-like TabView presentation.
- The main window contains only Transcribe; Settings opens independently with General, Recognition, Models & storage, Dictation, and AI post-processing categories. Recognition model, device, and thread controls are in Recognition.
- Transcribe makes the installed state of the supported model immediately distinguishable; its local size is available in Settings > Models & storage.
- No redundant explanatory settings subtitle or persistent local-transcription slogan appears in the Settings window.
- The file queue itself is the external drag-and-drop target for both empty and non-empty states; there is no separate drop panel above it.
- An empty queue shows a compact drop hint without a second Add files action, while Add files remains available in the Files toolbar.
- External file drag-and-drop does not interfere with built-in ListView row reordering, and the queue continues to define Transcribe all and Copy all order.
- Processing device and CPU threads remain accessible from Settings > Recognition without reserving space for removed decoder controls.
- Installed models do not reserve a Download button or duplicate Installed status line; downloading/error details remain visible when relevant.
- The file queue reads as the primary work area, status and progress are readable within each row, and primary, secondary, subtle, and destructive actions are visually distinguishable.
- Selecting a file row shows a rounded accent outline matching the row bounds without the default rectangular ListView selection chrome.
- The layout remains usable at reduced desktop width and height without overlapping controls or collapsing the queue into an impractical area.
- Settings > Models & storage exposes the installed-model list, actual sizes, total disk usage, download action, and destructive cleanup actions without a redundant status panel.
- Model download progress appears in a modal flow instead of as a permanent page block.
- Icon-only row actions render fully without clipping.
- Repeated colors, spacing, radii, typography, surfaces, buttons, and status presentation are defined through shared semantic resources.
- The functional behavior defined by IDD-0001 through IDD-0003 is preserved.
