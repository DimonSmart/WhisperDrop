# IDD-0002.spec-transcription-workspace

## Intent

The Transcribe workspace lets a user queue supported audio or video media, transcribe its audio locally in a deliberate order, inspect concise results, and copy completed text.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0003 — Model settings and availability
- IDD-0007 — Optional AI transcript post-processing
- IDD-0008 — Whisper decoding and repetition fallback

## Behavior

- Users add one or more files through drag and drop or the Add files action. The file-queue workspace acts as the external drag-and-drop target and visibly indicates when it can accept files.
- Source files are never copied, moved, or changed. A session keeps only their paths. Adding the same file again does not create a duplicate row.
- Supported extensions are `.wav`, `.mp3`, `.m4a`, `.aac`, `.flac`, `.ogg`, `.opus`, `.mp4`, `.m4v`, `.mov`, `.mkv`, and `.webm`. Extension matching is only an input/filter check; the media layer validates the container, audio stream, codec, and decoder. Video is used only as a source of audio. The application never launches FFmpeg as an external process.
- Each queued file shows a drag handle, file name, status, progress, language, Transcribe action, Copy action, and removal action. Full paths may be available without crowding the row.
- Recognition state is Pending, Preparing, Transcribing, Completed, or Error. Preparing performs local media decoding/resampling to transient 16 kHz mono PCM16 WAV; Transcribing then runs Whisper on that normalized WAV. Optional AI enhancement has its own independent state (not requested, pending, improving, completed, failed, or cancelled). AI failure never changes a successful recognition state to Error.
- Users can reorder files by drag and drop. The visual order determines both batch-transcription order and Copy all order. Reordering may be unavailable during an active batch and is available again afterward.
- Transcribe all processes files sequentially in current list order as Prepare → Transcribe → cleanup before moving to the next file. A file-specific media/recognition failure marks only that file as Error and processing continues. A bundled-media-runtime/ABI failure stops the batch and surfaces one application-level guidance message.
- A file's Transcribe action processes or retranscribes that one file. A later successful result replaces its earlier result.
- The active item exposes preparation or transcription progress without making the interface unresponsive; preparation may be indeterminate when source duration is unavailable. Other queued files remain Pending until their turn.
- Every file row has a read-only transcript Preview action. It is disabled until the first recognized segment is available, then may open a scrollable, selectable, copyable snapshot of the text recognized so far, including while a long file is still transcribing. The open dialog does not live-update; reopening it captures newer segments. A completed file previews its effective transcript instead. Restarting recognition clears any earlier partial text.
- After a successful result, hovering the file name or primary row area shows a wrapped, width-bounded preview of roughly the first 300–500 characters. The preview uses the effective transcript (processed when available, otherwise raw), may normalize whitespace, and truncates long previews with an ellipsis while retaining the complete session result. An empty successful result says "No speech recognized."
- Copy is enabled whenever an effective transcript exists. It copies the processed transcript after successful AI enhancement and otherwise copies the unchanged raw Whisper transcript. When a processed transcript exists, Copy raw exposes the original Whisper text separately.
- Copy all is enabled when at least one effective transcript exists. It copies effective transcripts in visual order, without file names and separated by one blank line; rows without any recognition result are skipped.
- Recognition language defaults to Auto. At minimum the user can choose Auto, English, Russian, and Spanish. Auto uses Whisper language detection and displays the detected language for the file; an explicitly selected language is displayed as the language used. Detection probability may be shown as supplementary information when available without a second recognition pass.
- Task defaults to Transcribe. Translate to English uses Whisper's translation mode and treats the selected language as the source-audio language.
- Vocabulary / context is an optional initial prompt passed unchanged to Whisper when it contains non-whitespace text; WhisperDrop does not synthesize or reinterpret that text.
- Advanced exposes the maximum previous-text context in tokens (1–224, default 224) as Uno's standard NumberBox, with inline step buttons and only theme-matching foreground/background/border overrides. Input is validated by NumberBox; the stored setting remains an integer clamped to the supported range. A separate Disable previous text context checkbox (off by default) disables the number field. These settings apply to subsequent Whisper processors; disabling the context takes precedence over the token limit but does not disable the optional vocabulary/initial prompt. The 224-token maximum reflects whisper.cpp's standard 448-token decoder text context, of which at most half is available for earlier text.
- Whisper normally decodes the whole prepared audio using fixed strict thresholds (entropy 1.8, log probability -0.8), without VAD. The decoder monitors newly recognized segments; on clear contiguous repeated phrases it stops the current native pass, preserves safely confirmed segments, decodes only the next short audio region (up to 45 seconds) via Beam Search and resumes primary decoding from the corrected region's last recognized boundary. The process never replaces an otherwise good whole transcript with a full-file re-decode. It limits repeated local repairs; any unresolved repeats trigger a user-visible quality warning. See IDD-0008.
- Progress reports native progress across the remaining audio and any bounded local repair, monotonically, with a small final allowance for recovery/finalization.
- CPU threads is an Advanced processor option. Auto leaves Whisper.net's thread default unchanged; an explicit value applies to subsequent recognition processors.
- Every single-file transcription captures an immutable recognition-options snapshot when it starts. Transcribe all captures one snapshot for the whole batch, so UI edits made during a running batch affect only later operations.

## Product-Significant Architecture And Constraints

- Recognition, media decoding/resampling, model loading, and model downloading must not block the UI.
- Sequential recognition reuses one loaded Whisper model for the queue and avoids multiple large in-memory model copies. Media preparation is also sequential, streaming, and owns only one transient normalized WAV at a time. When batch AI enhancement is enabled, the Whisper model is unloaded before the AI phase begins.

## Non-Goals

- The MVP does not provide a transcript editor, timestamps, a segment viewer, a subtitle timeline, or speaker labels.

## Acceptance Criteria

- A user can add supported audio/video files through either File Picker or drag-and-drop, reorder them, and see the chosen order used for batch transcription and Copy all. WAV, MP3, and MP4 are covered by bundled-runtime integration verification.
- The active row reports progress and language, a successful row exposes its text preview and Copy action, and an error row shows a usable reason.
- A batch continues after an individual file/content error, while a global bundled media runtime failure stops the batch without repeating the same failure for every row.
- Auto, English, Russian, and Spanish are selectable, and Auto displays a detected language after recognition.

## Verification

- Unit coverage exercises centralized format validation, Preparing → Transcribing state transitions, cancellation during preparation, file-error continuation, runtime-error batch stop, file ordering, retranscription replacement, language state, and Copy all ordering/filtering. Bundled-runtime integration fixtures verify WAV, MP3, and MP4 normalization to 16 kHz mono PCM16 WAV.
- User-interface coverage establishes drag-and-drop input, its Add files alternative, reorder availability, result preview behavior, action enabled states, and responsive progress updates.
- Local Whisper integration verification establishes that a locally available model can transcribe audio; ordinary continuous integration does not need to download or provide a model.
