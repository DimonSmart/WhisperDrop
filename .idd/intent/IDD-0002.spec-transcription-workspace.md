# IDD-0002.spec-transcription-workspace

## Intent

The Transcribe workspace lets a user queue supported audio files, transcribe them locally in a deliberate order, inspect concise results, and copy completed text.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0003 — Model settings and availability

## Behavior

- Users add one or more files through drag and drop or the Add files action. The drop zone visibly indicates when it can accept files.
- Source files are never copied, moved, or changed. A session keeps only their paths. Adding the same file again does not create a duplicate row.
- WAV is guaranteed for the MVP. Other common audio or video formats may be supported only when they remain self-contained and cross-platform; unsupported formats are rejected with a clear message. The application never launches FFmpeg as an external process.
- Each queued file shows a drag handle, file name, status, progress, language, Transcribe action, Copy action, and removal action. Full paths may be available without crowding the row.
- A file status is Pending, Transcribing, Completed, or Error. Errors expose a user-visible reason and do not damage other queued items.
- Users can reorder files by drag and drop. The visual order determines both batch-transcription order and Copy all order. Reordering may be unavailable during an active batch and is available again afterward.
- Transcribe all processes files sequentially in current list order. A failure marks only that file as Error and processing continues with the next file.
- A file's Transcribe action processes or retranscribes that one file. A later successful result replaces its earlier result.
- The active item exposes transcription progress without making the interface unresponsive; other queued files remain Pending until their turn.
- After a successful result, hovering the file name or primary row area shows a wrapped, width-bounded preview of roughly the first 300–500 characters. It may normalize whitespace and truncates long previews with an ellipsis, while retaining the complete unmodified result. An empty successful result says "No speech recognized."
- Copy is enabled only for a completed file and puts that file's complete transcript on the clipboard.
- Copy all is enabled only when at least one completed result exists. It copies completed transcripts only, in visual order, without file names and separated by one blank line; Pending and Error rows are skipped.
- Recognition language defaults to Auto. At minimum the user can choose Auto, English, Russian, and Spanish. Auto uses Whisper language detection and displays the detected language for the file; an explicitly selected language is displayed as the language used. Detection probability may be shown as supplementary information when available without a second recognition pass.
- Task defaults to Transcribe. Translate to English uses Whisper's translation mode and treats the selected language as the source-audio language.
- Vocabulary / context is an optional initial prompt passed unchanged to Whisper when it contains non-whitespace text; WhisperDrop does not synthesize or reinterpret that text.
- Skip silence is optional and uses the official Whisper.net Silero VAD API. Speech regions are recognized in source order and combined without adding pause/silence markers; an audio file with no detected speech completes successfully with an empty transcript.
- CPU threads is an Advanced processor option. Auto leaves Whisper.net's thread default unchanged; an explicit value applies to subsequent recognition processors.
- Every single-file transcription captures an immutable recognition-options snapshot when it starts. Transcribe all captures one snapshot for the whole batch, so UI edits made during a running batch affect only later operations.
- Progress comes from Whisper's native progress callback. With VAD enabled, VAD occupies an initial stage and the remaining progress is distributed monotonically across speech regions.

## Product-Significant Architecture And Constraints

- Recognition, audio decoding, model loading, and model downloading must not block the UI.
- Sequential processing reuses one loaded model for the queue and avoids multiple large in-memory model copies.

## Non-Goals

- The MVP does not provide a transcript editor, timestamps, a segment viewer, a subtitle timeline, or speaker labels.

## Acceptance Criteria

- A user can add multiple WAV files through either supported input path, reorder them, and see the chosen order used for batch transcription and Copy all.
- The active row reports progress and language, a successful row exposes its text preview and Copy action, and an error row shows a usable reason.
- A batch continues after an individual file error.
- Auto, English, Russian, and Spanish are selectable, and Auto displays a detected language after recognition.

## Verification

- Unit coverage exercises file ordering, sequential batch progression, continuation after an item error, progress state, retranscription replacement, language state, and Copy all ordering and filtering.
- User-interface coverage establishes drag-and-drop input, its Add files alternative, reorder availability, result preview behavior, action enabled states, and responsive progress updates.
- Local Whisper integration verification establishes that a locally available model can transcribe audio; ordinary continuous integration does not need to download or provide a model.
