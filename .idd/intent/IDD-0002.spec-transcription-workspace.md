# IDD-0002.spec-transcription-workspace

## Intent

The Transcribe workspace lets a user queue supported audio or video media, transcribe its audio locally in a deliberate order, inspect concise results, and copy completed text.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0003 — Model settings and availability
- IDD-0007 — Optional AI transcript post-processing
- IDD-0008 — Parakeet Ultra native recognition decision

## Behavior

- Users add one or more files through drag and drop or the Add files action. The file-queue workspace acts as the external drag-and-drop target and visibly indicates when it can accept files.
- A stopped macOS microphone recording is added to the same queue as a supported audio file. It remains Pending until the user starts transcription. Windows microphone recording remains unavailable in the current Windows runtime scope.
- Source files are never copied, moved, or changed. A session keeps only their paths. Adding the same file again does not create a duplicate row.
- Supported extensions are `.wav`, `.mp3`, `.m4a`, `.aac`, `.flac`, `.ogg`, `.opus`, `.mp4`, `.m4v`, `.mov`, `.mkv`, and `.webm`. Extension matching is only an input/filter check; the media layer validates the container, audio stream, codec, and decoder. Video is used only as a source of audio. The application never launches FFmpeg as an external process.
- Each queued file shows a drag handle, file name, status, progress, language, Transcribe action, Copy action, and removal action. Full paths may be available without crowding the row.
- Recognition state is Pending, Preparing, Transcribing, Completed, Incomplete, Cancelled, or Error. Preparing performs local media decoding/resampling to transient 16 kHz mono audio; Transcribing runs the native recognizer on that prepared audio. Optional AI enhancement has its own independent state (not requested, pending, improving, completed, failed, or cancelled). AI failure never changes a successful recognition state to Error.
- Users can reorder files by drag and drop. The visual order determines both batch-transcription order and Copy all order. Reordering may be unavailable during an active batch and is available again afterward.
- Transcribe all performs recognition sequentially in current list order. A file-specific media or recognition failure affects only that file and processing continues. A bundled-media or native-runtime failure stops the batch and surfaces one application-level guidance message. When batch AI enhancement is enabled, all recognition work finishes and the native model is unloaded before the AI phase processes successful results in list order.
- A file's Transcribe action processes or retranscribes that one file. A later successful result replaces its earlier result.
- The active item exposes preparation or transcription state without making the interface unresponsive; progress may be indeterminate when the active stage does not provide an accurate progress value. Other queued files remain Pending until their turn.
- The recognizer does not stream segments during a run. A file's read-only transcript Preview becomes available after recognition completes and opens a scrollable, selectable, copyable snapshot of the result. A completed file previews its effective transcript. Restarting recognition clears the earlier result.
- After a successful result, hovering the file name or primary row area shows a wrapped, width-bounded preview of roughly the first 300–500 characters. The preview uses the effective transcript (processed when available, otherwise raw), may normalize whitespace, and truncates long previews with an ellipsis while retaining the complete session result. An empty successful result says "No speech recognized."
- Copy is enabled whenever an effective transcript exists. It copies the processed transcript after successful AI enhancement and otherwise copies the unchanged raw recognition text. When a processed transcript exists, Copy raw exposes the original recognition text separately.
- Copy all is enabled when at least one effective transcript exists. It copies effective transcripts in visual order, without file names and separated by one blank line; rows without any recognition result are skipped.
- Recognition language is Auto-detected. The workspace displays a language only when the recognizer returns one; it does not imply a single language label is accurate for every segment in code-switched audio.
- ASR performs source-language transcription only. There is no translation task, language selector, vocabulary prompt, previous-text context, beam-search, entropy, or other Whisper-specific decoder control.
- The native model processes the prepared long-form audio in one non-streaming run. The application does not add a second VAD or arbitrary overlapping chunking by default. Any incomplete/truncated result is marked Incomplete and is not treated as a completed transcript or sent to AI correction automatically.
- Progress reflects only available stage information. When the recognizer does not provide accurate progress, the workspace shows an indeterminate recognition state rather than invented percentages. Cancellation remains available.
- CPU threads is a recognition option only when the native runtime supports it. An explicit setting applies to subsequent runs; unsupported values or runtime behavior are not simulated.
- Raw full text, punctuation, whitespace, returned language, and available source-ordered segments remain available after a successful run. Segment IDs are unique within the result; timestamps are global to the original file, nonnegative, ordered, and satisfy `start <= end`. Segment text corresponds to the raw full text apart from whitespace normalization. If native segments need grouping, the application does not invent timing precision. Unsupported probability/confidence values are `null` rather than estimates.
- Every single-file transcription captures an immutable recognition-options snapshot when it starts. Transcribe all captures one snapshot for the whole batch, so UI edits made during a running batch affect only later operations.

## Product-Significant Architecture And Constraints

- Recognition, media decoding/resampling, model loading, and model downloading must not block the UI.
- Sequential recognition reuses one loaded native model for queue items and avoids multiple model copies. Media preparation is sequential and owns only one transient normalized output at a time. When batch AI enhancement is enabled, the native model is unloaded before the AI phase begins.

## Non-Goals

- The MVP does not provide a transcript editor, timestamps or a segment viewer, a subtitle timeline, or speaker labels.

## Acceptance Criteria

- A user can add supported audio/video files through either File Picker or drag-and-drop, reorder them, and see the chosen order used for batch transcription and Copy all. WAV, MP3, and MP4 are covered by bundled-runtime integration verification.
- A stopped macOS microphone recording appears as a Pending WAV queue item and can be transcribed through the existing single-file or batch actions; it is not transcribed automatically. Windows clearly presents the unavailable microphone state.
- The active row reports progress and language, a successful row exposes its text preview and Copy action, and an error row shows a usable reason.
- A batch continues after an individual file/content error, while a global bundled media or native-runtime failure stops the batch without repeating the same failure for every row.
- Auto language detection displays a returned language after recognition and does not invent a fallback language.
- Incomplete native output is clearly distinguished from Completed and is unavailable for automatic AI correction.
- Recognition covers the pinned model's declared 25 European languages, including Russian, English, and Spanish. Verification exercises those languages and code-switched audio rather than inferring support from a model label alone.
- A recording of at least 64 minutes, or an agreed equivalent, completes without missing or repeated speech around long pauses and the model's short segment boundaries.

## Verification

- Unit coverage exercises centralized format validation, Preparing → Transcribing state transitions, cancellation during preparation and recognition, file-error continuation, runtime-error batch stop, file ordering, retranscription replacement, returned-language state, incomplete-result handling, and Copy all ordering/filtering. Bundled-runtime integration fixtures verify WAV, MP3, and MP4 normalization to 16 kHz mono audio.
- User-interface coverage establishes drag-and-drop input, its Add files alternative, reorder availability, result preview behavior, action enabled states, and responsive progress updates.
- Microphone flow review establishes that stopping a macOS recording adds one Pending queue item, recording does not start recognition, and Windows clearly presents the unavailable state.
- Local Parakeet integration verification establishes that a locally available model can transcribe audio; ordinary continuous integration does not download or provide the model.
