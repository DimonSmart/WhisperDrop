# IDD-0008.adr-whisper-decoding-fallback

## Status

Accepted — 2026-10-25

## Context

WhisperDrop (Whisper.net 1.9.1, whisper.cpp 1.8.5) exhibited catastrophic repetitive decoding on a long, predominantly Spanish recording with intermittent English. The purpose of six-profile diagnostic runs was to select one understandable, maintainable recognition strategy rather than ship multiple configurable decoding modes.

The same recording was tested without VAD and with Silero VAD:

| Approach | Observation |
| --- | --- |
| Default greedy decoding, no VAD | After otherwise plausible text, repeated `[HABLANDO EN INGLÉS]` roughly 1,200 times; substantial speech lost. About 185 seconds. |
| Strict fallback, no VAD (`entropy_thold=1.8`, `logprob_thold=-0.8`) | Most useful complete transcript, without catastrophic looping. About 236 seconds. Some English passages represented by markers or minor recognition errors. |
| Beam Search, no VAD | Substantial, largely complete transcript with fewer missing English passages, but possible language/translation errors and around 502 seconds. |
| Initial temperature 0.2, no VAD | Another substantial repetition loop, around 748 seconds. |
| No-speech threshold 0.4, no VAD | Did not materially improve the strict-fallback result. |
| VAD enabled | Prevented the earlier catastrophic loop but introduced many short repeated phrases; each run took about 31–38 minutes. Current VAD integration restarted recognition separately per speech region. |

These are qualitative comparisons of transcripts from the same audio, **not** word-error-rate benchmarks against a verified reference transcript. The failure-free result on this recording is not a guarantee against all omissions or hallucinations.

## Decision

- Expose **one** recognition flow to users. Remove temporary six-experiment reporting, VAD processing/model download/UI/settings, and diagnostic-only tests.
- Default to whole-file Whisper decoding (no VAD), with the fixed and non-user-configurable `entropy_thold=1.8` and `logprob_thold=-0.8`. Preserve ordinary user choices of recognition model, language, Transcribe/Translate task, prompt, CPU threads, and processing device.
- After the primary pass, look for obvious **contiguous** repeated sequences of 3–32 normalized words occurring at least three times. This catches short loop markers as well as repeated phrases; normal isolated repetitions are not automatically removed.
- Only when that check triggers, retry the full recording **once** using Beam Search with the same strict thresholds and ordinary recognition options. Choose the retry only if it reduces detected repetitions without discarding most of the nonrepetitive text. On retry failure keep the primary result; never silently replace good text with an empty/truncated output.
- If the selected transcript still has an obvious repeated sequence, surface a visible quality warning. Do not automatically delete or hallucinate missing content.
- Raw recognition remains the input to the separately optional AI transcript post-processing stage; AI correction is not relied upon to reconstruct large lost sections.

## Alternatives Considered

- Always use Beam Search: improved some multilingual sections, but substantially slower without a clear overall advantage.
- Increase initial temperature or tighten no-speech threshold: did not resolve looping in the observed runs.
- Use VAD for every file: substantially slower and currently introduces short repeated phrases and context degradation at region boundaries.
- Detect, cut and rerecognize specific time spans, stitch overlaps or introduce additional complex scoring: rejected as disproportionate to the immediate requirement.

## Consequences

- Most files are decoded only once. A rare suspicious file may require one additional full pass.
- Both decoding thresholds are implementation constants, not saved user settings.
- The repetition heuristic is intentionally simple. It cannot prove accuracy, detect arbitrary nonrepeating hallucinations, or guarantee detection of missing speech; those limitations are acceptable for the initial product stage.
- If no candidate eliminates repeats, preserve the better available text and visibly flag it for inspection.
- Keep normal batch, partial preview, cancellation, original-result preservation and optional AI workflow behavior.
