# IDD-0001.spec-local-desktop-transcription

## Intent

ParakeetDrop is a deliberately minimal desktop application for transcribing audio and video files locally. Local processing is a product guarantee, not a slogan that must be repeated in the primary interface.

## Related Specifications

- IDD-0002 — Transcription workspace
- IDD-0003 — Model settings and availability
- IDD-0007 — Optional AI transcript post-processing
- IDD-0008 — Parakeet Ultra native recognition decision

## Behavior

- The current required release target is macOS Apple Silicon (ARM64). Windows x64 is planned for a later stage and is not currently verified or release-ready. macOS x64 is unsupported.
- The main window provides Transcribe, Models, and AI destinations and always opens on Transcribe.
- The primary interface does not continuously repeat explanatory local-processing/privacy copy above navigation or inside Models.
- Parakeet Ultra recognition is local and never sends source audio, file names, paths, or file metadata to a recognition service. AI transcript post-processing is a separate opt-in stage: when explicitly enabled or invoked, transcript text may be sent only to the endpoint explicitly configured by the user. The default AI endpoint is loopback/local and ParakeetDrop has no built-in cloud AI destination. Recognition-model downloads remain explicit user-initiated network activity.
- Application diagnostics never record audio, transcript text, file names or paths, or AI prompts and responses.
- Once the Parakeet Ultra Q8_0 model is downloaded, supported audio/video media preparation and recognition work offline. Media decoding never initiates network access. AI post-processing is optional and its availability never gates raw local transcription.
- The distributed application is self-contained: users do not manually install FFmpeg, Python, a recognition CLI, codecs, native runtimes, or other dependencies. A pinned FFmpeg shared-library runtime and the native recognition runtime are bundled with the application and loaded only in-process; system/Homebrew FFmpeg and command-line recognizers are never used.
- File lists, transcription results, and recognition history are session data. They are discarded when the application closes and no transcript files are created automatically.
- If no recognition model is installed, Transcribe remains the initial destination and presents model availability/download controls without automatically starting network activity.
- Recognition transcribes speech in its source language with automatic language detection. ASR translation to English is not supported.
- On macOS, the Transcribe workspace can record audio from the system's selected input microphone. The operating system requests microphone permission when recording is first attempted. Stopping a recording adds it to the session queue as audio and does not start transcription automatically. Windows shows microphone capture as unavailable until that platform is implemented.
- Microphone recordings are local session data: they are stored temporarily for the current application session, are not sent to a recognition service, and are removed with other transient session media.
- Processing-device selection offers Auto, CPU, and GPU. Auto prefers the supported Metal or Vulkan backend and falls back to CPU when unavailable; CPU forces CPU inference; GPU reports an actionable error when that platform's required backend is unavailable. The application reports the backend actually used and indicates when a changed device setting requires model reload or restart.
- ParakeetDrop uses its own application identity and `ParakeetDrop` data directory. It does not read, migrate, or delete settings, models, or other data from an earlier WhisperDrop installation; both installations may coexist.

## Product-Significant Architecture And Constraints

- The product must package all prerequisites needed for its supported transcription formats and supported platforms, including the mandatory bundled media-decoding runtime.
- The current release build requires verification on a clean macOS ARM64 environment with no separately installed FFmpeg or recognition runtime. Metal support is established only by a recognition run on Apple Silicon that reports the Metal backend. Windows verification is deferred to its later platform stage.
- Local recognition and model inventory must remain usable without any network request after the model has been downloaded.

## Non-Goals

- Transcription history, automatic text-file saving, transcript editing, cloud recognition, ASR translation, summarization, diarization, subtitle editing, SRT/VTT export, and parallel recognition are outside the MVP. Optional transcript correction through a user-configured OpenAI-compatible endpoint is defined separately by IDD-0007.
- Automatic migration or compatibility with previous WhisperDrop installations, settings, model folders, application identities, or updater/Cask names is not required. Users manage old installations and their data themselves.
- Running on macOS Intel, including through Rosetta, is outside the supported platform set.
- The application does not automatically download a model.
- Persistent privacy/local-processing promotional copy in the main navigation area is not required.

## Acceptance Criteria

- A user can launch the current ParakeetDrop release on macOS Apple Silicon and immediately see the Transcribe workspace regardless of whether a model is installed.
- No persistent local-processing/privacy slogan is rendered above navigation or repeated across the Transcribe/Models destinations.
- When the selected model is unavailable, Transcribe makes that state and the download action clear without redirecting the user to Models.
- After Parakeet Ultra Q8_0 has been downloaded, the user can transcribe supported WAV, audio, and video media without a network connection.
- Closing and reopening the application leaves the transcription workspace empty while retaining ParakeetDrop settings and the downloaded model.
- The current macOS ARM64 release does not require a separately installed media or recognition prerequisite; its package carries the required media and native recognition runtimes. Windows remains planned for a later stage and is not a current release acceptance gate.

## Verification

- Current platform release verification establishes that the application launches and performs supported offline transcription on a clean macOS Apple Silicon environment. Windows remains unverified until its later platform stage; macOS Intel is unsupported.
- Privacy review establishes that source audio and file metadata have no external recognition transmission path; AI transcript transmission exists only behind explicit opt-in/invocation and targets only the endpoint configured by the user. Model download remains explicit.
- UI review establishes that local-processing/privacy copy is not persistently duplicated in the primary Transcribe/Models navigation surface.
- Session-lifecycle coverage establishes that transcription workspace data is not restored after a new launch.
- Microphone verification establishes that macOS permission is requested through the operating system, a stopped recording enters the queue without starting recognition, and recording audio remains transient and local. Windows exposes the unavailable state without attempting capture.
