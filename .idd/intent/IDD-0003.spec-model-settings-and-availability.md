# IDD-0003.spec-model-settings-and-availability

## Intent

Settings allow users to choose where Whisper models are stored, select a recognition model and language, explicitly download the selected model, and understand whether transcription is available.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0002 — Transcription workspace

## Behavior

- Settings provides a Models folder field and Browse action. Its default is the platform-specific application-data directory, and changing it immediately re-evaluates whether the selected model is present.
- Settings provides a model selector with at least Tiny, Base, Small, Medium, Large V3 Turbo, Large V3, Tiny English, Base English, Small English, Medium English, Large V2, and Large V1. English-only models are clearly marked; approximate model sizes may be shown. Base is the initial selection.
- The selected model state is Not downloaded, Downloading, Downloaded, or Error. An already present model is not downloaded again.
- Download model is an explicit user action. Downloading shows progress when known, or a clear indeterminate downloading state when total size is unknown, without freezing the UI.
- A download is written as a temporary .download file and becomes available only after a successful atomic finalization. Failed or incomplete downloads do not leave a corrupt available model file.
- Transcribe and Transcribe all are unavailable when the selected model is absent and direct the user to download it in Settings. They do not start a download themselves.
- Models folder, selected model, and recognition language persist between launches. Runtime data such as a current transcription, progress, active file, and transcripts does not persist.
- Settings persistence is atomic: an interrupted write does not replace a valid saved settings state.
- On launch, the application loads settings, derives the models folder, checks the selected model's presence, displays an empty workspace, performs no network request, and does not load a model into memory until transcription is requested.

## Product-Significant Architecture And Constraints

- Model download and persistence must preserve a usable prior state when a download, directory operation, or settings write fails.

## Non-Goals

- The application does not bundle a Whisper model in its initial distribution.

## Acceptance Criteria

- A user can change and retain a models folder, select and retain a model and recognition language, and observe the correct selected-model state on a later launch.
- A user sees download progress and can transcribe only after a complete selected-model download.
- An interrupted download or unavailable model directory yields an actionable error without presenting a partial model as downloaded.
- Launching the application makes no network request and does not eagerly load a model.

## Verification

- Unit coverage establishes settings defaults, loading and persistence, default model-directory selection, model-path and presence detection, cleanup after download error, and selected-model availability behavior.
- User-interface coverage establishes model-state messaging, unavailable-transcription guidance, browse behavior, and download progress presentation.
- Continuous integration builds and runs unit tests for Windows and macOS without downloading multi-gigabyte models; Linux may be included when supported without special architecture.
