# IDD-0003.spec-model-settings-and-availability

## Intent

ParakeetDrop keeps transcription focused on files and exposes a compact selected-model status there. Model selection, recognition performance, and model management are configured in dedicated categories of a separate Settings window. Users can see whether the model is installed, how much disk space it uses, download it explicitly, and remove it without requiring network access merely to inspect availability.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0002 — Transcription workspace

## Behavior

- The Transcribe workspace shows the selected model name and installed status, with a direct download shortcut when the model is missing. Model selection belongs to Settings > Recognition.
- Parakeet Ultra Q8_0 is the only model offered in the first product version. Processing device defaults to Auto and CPU threads default to Auto. New-install settings persist between launches.
- Settings > Recognition owns model selection, processing device, and CPU-thread controls. These controls remain available independently of whether a model is installed.
- Settings > Models & storage provides a Models folder field and Browse action. Its default is the ParakeetDrop application-data directory, and changing it immediately re-evaluates installed-model state.
- The local model catalog contains only `parakeet-ultra-Q8_0.gguf`; it does not show unavailable model families or quantizations. The pinned model revision, download URL, exact byte size, and SHA-256 identify the supported artifact.
- Showing the model catalog never requires a network request. Internet access is used only after the user explicitly starts a recognition-model download.
- Processing device is Auto / CPU / GPU. On macOS ARM64, CPU always selects CPU inference, Auto prefers Metal when available and falls back to CPU, and GPU reports an actionable error when Metal is unavailable. On Windows x64, CPU selects CPU inference, Auto prefers Vulkan when available and falls back to CPU, and GPU reports an actionable error when Vulkan is unavailable. macOS x64 is unsupported.
- Models recognizes the supported model only when its bytes match the pinned artifact and reports its actual on-disk size.
- Users can delete the supported model. Deletion releases any active model resources first and must not remove unrelated files from a user-selected folder.
- Destructive model deletion is confirmed by the UI and reports file-system failures rather than silently ignoring them.
- Download model opens a modal model-management flow for the single supported model. It identifies the model and its exact byte size before download; the modal shows byte progress when known and an indeterminate state otherwise.
- A model download can be cancelled. Downloads use a temporary .download file and become installed only after successful atomic finalization. Failed or cancelled downloads do not leave a corrupt installed model file.
- Download failures distinguish a missing artifact, rate limiting, and TLS/network failure with an actionable explanation.
- The Transcribe workspace shows whether the supported recognition model is installed and exposes a direct Download action when it is not.
- Transcribe and Transcribe all remain unavailable while the model is absent or invalid. Attempting transcription without a valid model keeps the user in the Transcribe workspace and explains that the model must be downloaded or repaired.
- On launch, ParakeetDrop always opens the Transcribe workspace, loads its own settings, scans only the configured local models folder, displays an empty workspace, performs no network request, and does not load the Parakeet model into memory until transcription is requested.
- The application does not automatically start a model download or force the Settings window to open when the model is not installed.
- ParakeetDrop uses the new application identity `io.dimonsmart.parakeetdrop` and the `ParakeetDrop` data location. It does not import or migrate settings, models, or model-folder choices from WhisperDrop; earlier application data remains untouched.
- Runtime data such as a current transcription, progress, active file, and transcripts does not persist.
- Settings persistence is atomic: an interrupted write does not replace a valid saved settings state. Missing or invalid new values normalize independently so a partially malformed ParakeetDrop settings document does not discard other valid settings.

## Product-Significant Architecture And Constraints

- Model availability and installed-model inventory are derived from local files and the pinned one-model catalog; inspecting them never downloads remote model data.
- Model download and persistence must preserve a usable prior state when a download, directory operation, or settings write fails.
- Model deletion operates only on paths derived from the known model catalog.

## Non-Goals

- The application does not bundle the Parakeet model in its initial distribution.
- Parakeet V3, Whisper models, additional Parakeet quantizations, and remotely fetched model catalogs are outside the first product version.
- Compatibility migration for earlier settings and model folders is not provided; previous application data is not scanned or deleted.

## Acceptance Criteria

- The supported Parakeet Ultra Q8_0 model, processing device, and CPU threads are selectable from Settings > Recognition, and all choices persist across launches. The Transcribe workspace presents model status and the missing-model Download shortcut.
- Transcribe shows whether the selected model is installed; Settings > Models & storage shows the installed model's actual local size and total disk usage.
- Settings > Models & storage shows the configured storage folder, the supported model's actual file size, and its total disk usage.
- Users explicitly start download of the pinned model from a modal flow with byte progress and cancellation. The model name and exact byte size are shown before download.
- Users can delete the installed model without deleting unrelated files in the selected folder.
- The selected-model availability shown on Transcribe updates after changing folders, downloading, or deleting models in Settings.
- An interrupted, failed, or cancelled download never presents a partial model as installed.
- Missing artifacts, rate limiting, and TLS/network failures are distinguishable to the user and do not mark a model as installed.
- Launching ParakeetDrop makes no network request, does not eagerly load the model, and opens Transcribe even when it is not installed. Earlier WhisperDrop data is neither loaded nor removed.

## Verification

- Unit coverage establishes new-install settings defaults and persistence, model-path and presence detection, pinned-artifact size/hash verification, safe model deletion, cleanup after download error, and selected-model availability behavior without testing legacy-data migration.
- Workspace coverage establishes that unavailable transcription remains in the primary workspace and surfaces download guidance.
- User-interface coverage should establish recognition controls in Settings > Recognition, model management in Settings > Models & storage, confirmation flows, browse behavior, and modal download progress.
- Windows runtime verification exercises the bundled CPU runtime and a real local-model transcription; Vulkan is additionally exercised on supported Windows GPU hardware. The model is not downloaded in routine CI; model and hardware checks run separately in an explicitly controlled environment.
