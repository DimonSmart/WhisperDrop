# IDD-0003.spec-model-settings-and-availability

## Intent

WhisperDrop keeps recognition choices close to transcription while giving downloaded Whisper models their own local storage-management surface. Users can see which models are installed, how much disk space they use, download additional models explicitly, and remove installed models without requiring network access merely to inspect available choices.

## Related Specifications

- IDD-0001 — Local desktop transcription
- IDD-0002 — Transcription workspace
- IDD-0004 — Compact visual system

## Behavior

- The Transcribe destination owns recognition model, language, task, vocabulary/context, voice detection, processing device, and CPU-thread controls because those choices affect recognition behavior.
- The selected recognition model defaults to Base and the recognition language defaults to Auto-detect. Task defaults to Transcribe, vocabulary/context to empty, Skip silence to off, Processing device to Auto, and CPU threads to Auto. All persist between launches.
- The Models destination owns model storage and lifecycle management rather than recognition behavior.
- Models provides a Models folder field and Browse action. Its default is the platform-specific application-data directory, and changing it immediately re-evaluates installed-model state.
- The application contains a local model catalog with at least Tiny, Base, Small, Medium, Large V3 Turbo, Large V3, Tiny English, Base English, Small English, Medium English, Large V2, and Large V1. English-only variants remain distinguishable and approximate download sizes may be shown.
- Showing the model catalog never requires a network request. Internet access is used only after the user explicitly starts a recognition-model or VAD-model download.
- User-facing recognition models and the internal Silero VAD model are separate inventories. The VAD model is stored under application data, never appears in the recognition-model dropdown, is not counted as an installed recognition model, and is not stored in the user-selected Models folder.
- Enabling Skip silence when the VAD model is absent offers an explicit cancellable download. The download uses a temporary file and atomic finalization; launch never downloads VAD implicitly.
- Processing device is Auto / CPU / GPU. CPU is always the safe fallback. Auto may use only acceleration shipped by the current build and falls back to CPU. The current 1.9.1 packaging can use the bundled Metal backend on macOS; unsupported GPU requests produce an actionable error rather than loading an incompatible runtime.
- Native runtime selection is configured once before the first WhisperFactory or WhisperVadFactory. A device change after initialization is persisted for the next launch and shows Restart required; recreating only a factory is not treated as runtime switching.
- Models shows every recognized downloaded model in the configured folder, its actual on-disk file size, and the combined size of all recognized downloaded models.
- Users can delete one downloaded model or delete all downloaded models. Delete-all removes only files that correspond to known Whisper catalog models and must not delete unrelated files from a user-selected folder.
- Before deleting a model that may currently be loaded, the recognition runtime releases its loaded model resources.
- Destructive model deletion is confirmed by the UI and reports file-system failures rather than silently ignoring them.
- Download model opens a modal model-management flow. The model can be selected from the local catalog, approximate size is shown before download, and the modal surface shows determinate progress when total bytes are known or an indeterminate state otherwise.
- A model download can be cancelled. Downloads use a temporary .download file and become installed only after successful atomic finalization. Failed or cancelled downloads do not leave a corrupt installed model file.
- The Transcribe destination shows whether the selected recognition model is installed and exposes a direct Download action when it is not.
- The recognition-model dropdown visually marks installed models with an Installed indicator and their actual local file size. Installed models are grouped first while preserving catalog order within the installed and not-installed groups.
- Transcribe and Transcribe all remain unavailable while the selected model is absent. Attempting transcription with an unavailable model keeps the user in the Transcribe destination and explains that the selected model must be downloaded.
- On launch, WhisperDrop always opens the Transcribe destination, loads settings, scans only the configured local models folder, displays an empty workspace, performs no network request, and does not load a Whisper model into memory until transcription is requested.
- The application does not automatically start a model download or force the Models destination to open when no models are installed.
- Runtime data such as a current transcription, progress, active file, and transcripts does not persist.
- Settings persistence is atomic: an interrupted write does not replace a valid saved settings state. Missing or invalid newly introduced values normalize independently so an older or partially malformed settings document does not discard valid model/folder/language choices.

## Product-Significant Architecture And Constraints

- Model availability and installed-model inventory are derived from local files and the built-in model catalog.
- Model download and persistence must preserve a usable prior state when a download, directory operation, or settings write fails.
- Model deletion operates only on paths derived from the known model catalog.

## Non-Goals

- The application does not bundle a Whisper model in its initial distribution.
- The model catalog is not fetched remotely and does not act as a general-purpose file browser.

## Acceptance Criteria

- Recognition model and language are selectable from Transcribe and remain persisted across launches.
- Opening the recognition-model dropdown makes installed models immediately distinguishable, shows their actual local size, and places installed entries before models that are not installed.
- Models shows the configured storage folder, all recognized installed models, each model's actual file size, and their total disk usage.
- Users can explicitly download any catalog model from a modal flow with visible progress and cancellation.
- Users can delete one installed model or all installed models without deleting unrelated files in the selected folder.
- The selected-model availability shown on Transcribe updates after changing folders, downloading, or deleting models.
- An interrupted, failed, or cancelled download never presents a partial model as installed.
- Launching the application makes no network request, does not eagerly load a model, and opens Transcribe even when no model is installed.

## Verification

- Unit coverage establishes settings defaults and persistence, model-path and presence detection, local inventory size reporting, safe delete-all behavior, cleanup after download error, and selected-model availability behavior.
- Workspace coverage establishes that unavailable transcription remains on Transcribe and surfaces download guidance.
- User-interface coverage should establish model-management presentation, confirmation flows, browse behavior, and modal download progress.
- Continuous integration builds and runs unit tests for Windows and macOS without downloading multi-gigabyte models; Linux may be included when supported without special architecture.
