# ENG-0002.rule-whisper-local-runtime

## Rule

Use Whisper.net with a stable bundled Whisper runtime for local recognition. Reuse a WhisperFactory for the selected model across sequential transcription operations, and release the previous factory when the selected model changes.

## Applicability

Conditional

## Applies when

- implementing or changing local transcription, Whisper-model management, or recognition execution

## Rationale

The selected runtime supports the product's local-processing promise while factory reuse prevents unnecessary repeated loading of large models.

## Guidance

- Create a recognition processor per operation when that makes progress and language state easier to manage.
- Package required runtime components with the application rather than requiring a user-installed prerequisite.
- Use Whisper's supported `GgmlType` values as the model catalog source. Keep display names, English-only labels, approximate sizes, and model identifiers together in a catalog that maps selected models to runtime types.
- Prefer the runtime's supported language catalog when it provides the required display names and language codes. Otherwise keep an explicit display-name-to-Whisper-language-code catalog separate from UI labels.

## Verification

Recognition integration demonstrates local execution with the selected model, model-factory reuse across sequential work, and safe disposal when the selected model changes. Model and language catalogs map user selections to valid runtime identifiers without coupling display text to recognition codes.
