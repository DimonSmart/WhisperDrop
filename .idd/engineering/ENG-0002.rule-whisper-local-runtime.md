# ENG-0002.rule-whisper-local-runtime

## Rule

Use Whisper.net 1.9.1 or later with the native runtime packaged by WhisperDrop. Configure process-global runtime selection exactly once before the first `WhisperFactory` or `WhisperVadFactory`, reuse factories by model/lifecycle, and create processors from immutable recognition-option snapshots.

## Applicability

Conditional

## Applies when

- implementing or changing local transcription, VAD, Whisper-model management, runtime packaging, or recognition execution

## Rationale

Whisper.net's native library choice becomes process-global when the first Whisper/VAD factory touches the runtime. Treating device selection as an ordinary processor option would create misleading hot-switch behavior. Factory reuse avoids reloading large recognition models, while a separate VAD lifecycle keeps the small internal Silero model independent from user recognition models.

## Guidance

- Configure `RuntimeOptions` only in the runtime-selector responsibility and only before first native initialization. Do not reset `LoadedLibrary`, force-reload a DLL/dylib, or claim that disposing `WhisperFactory` changes native runtime.
- `Auto` considers only backends actually shipped by WhisperDrop. CPU remains the mandatory fallback.
- `CPU` uses the bundled portable runtime with `WhisperFactoryOptions.UseGpu = false`.
- `GPU` is exposed only through supported packaged acceleration. With the current package set, macOS can use the bundled Metal backend; unsupported systems receive a user-facing availability error.
- Keep recognition-model and VAD-model factories separate. Changing/deleting a recognition model must not invalidate the VAD model.
- Build one Whisper processor per operation or VAD speech region. Apply language detection, translation, prompt, thread count, offset/duration, and progress callback at processor-builder level.
- Auto language uses `WithLanguageDetection()`; do not pass the literal `"auto"` through `WithLanguage(...)`.
- VAD uses `WhisperVadFactory` / `WhisperVadProcessor` and default Silero tuning unless a later intent explicitly exposes tuning.
- Package required runtime components with the application rather than requiring Python, whisper.cpp, a command-line executable, or manually downloaded native libraries.
- Preserve build/publish verification for the package's `build/win-*` and `build/macos-*` native layout when updating Whisper.net.

## Verification

Tests cover settings snapshots, restart-required semantics, VAD resource lifecycle, batch consistency, and model/factory lifecycle where practical. A local opt-in integration test exercises a real model. Build/publish must fail clearly if mandatory bundled runtime files are no longer present at the expected package paths.
