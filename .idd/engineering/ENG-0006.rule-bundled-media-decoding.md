# ENG-0006.rule-bundled-media-decoding

## Applicability

Conditional

## Applies when

Apply this rule whenever code changes media input, decoding, media packaging, temporary normalized audio, or the boundary between media preparation and speech recognition.

## Rule

- Media decoding is in-process. Do not launch `ffmpeg`, `ffprobe`, shell commands, or a process wrapper around FFmpeg.
- Use the pinned application-bundled FFmpeg runtime. Never fall back to `PATH`, Homebrew, a system FFmpeg installation, or the current working directory.
- Keep managed bindings and native FFmpeg ABI compatible and pinned. A runtime mismatch is a configuration/runtime failure, not an individual-file error.
- The media layer owns container probing, best/default audio-stream selection, decoding, resampling, temporary normalized audio, and FFmpeg resource cleanup.
- The recognition layer remains media-format agnostic. `IRecognitionService` receives normalized WAV and must not acquire container/codec/FFmpeg responsibilities.
- Normalize every supported input, including WAV, once to 16 kHz mono PCM WAV before recognition. Adapt those decoded samples to the native recognition API's required sample representation without decoding the source media again.
- Decode and resample incrementally into the application-owned temporary media output. Avoid keeping multiple full-recording sample copies in memory when preparing the native recognition input.
- For video containers, read packets required to reach the selected audio stream but never create or run a video decoder.
- Flush both the audio decoder and resampler at end-of-stream so final samples are not lost.
- All FFmpeg native resources and source-file locks are released deterministically on success, error, and cancellation.
- Temporary normalized WAV files live only under the application's dedicated `ParakeetDrop` temp area, are never user output, and are deleted after success, recognition failure, media failure, or cancellation. Stale cleanup is best-effort and may touch only application-owned temp files.
- File-specific media errors mark only that queue item and allow a batch to continue. Bundled-runtime/ABI errors stop the batch and surface one actionable application-level error.
- Release artifacts must include required shared media libraries, exclude the FFmpeg CLI executables, include third-party notices, and verify native dependency/checksum information from the final packaged artifact.

## Rationale

This preserves a stable recognition boundary while allowing containers/codecs to evolve independently, keeps media work local/offline, prevents hidden machine-level dependencies, and makes native distribution auditable.
