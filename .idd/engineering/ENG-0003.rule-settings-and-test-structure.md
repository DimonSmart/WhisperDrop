# ENG-0003.rule-settings-and-test-structure

## Rule

Persist user settings in a simple JSON document through a focused settings service. Normalize newly introduced settings independently, keep transcription execution based on immutable snapshots, and keep the solution to one production application project plus one test project unless another project has clear practical value.

## Applicability

Conditional

## Applies when

- implementing or changing settings persistence, recognition options, project structure, or local model integration verification

## Rationale

The application is intentionally small, but recognition settings can change while work is running. Atomic persistence and snapshot semantics make behavior predictable without introducing a larger state-management framework. A model integration check provides evidence that local recognition works without requiring a large model download on routine CI.

## Guidance

- Write settings atomically through a temporary file and replace/move operation.
- Normalize missing or invalid new settings independently without discarding unrelated valid settings.
- Keep user-entered text as text; do not generate or reinterpret it before persistence or recognition.
- A single transcription captures one recognition-options snapshot at start. `Transcribe all` captures one snapshot for the entire batch.
- If changing a native device requires rebuilding the model or restarting the application, surface that behavior instead of implying an immediate switch.
- Keep routine CI independent of downloading the Parakeet model or accessing real GPU hardware. Run model and hardware integration checks only in an explicitly controlled environment with the required model and device.
- Keep build and test commands in verification configuration rather than duplicating operational commands in this rule.

## Verification

Settings coverage establishes new-install defaults, round-trip persistence, tolerant normalization, and atomic writes. Workspace coverage establishes single-file and batch snapshot semantics. A distinct local-model integration check exists, and routine CI does not download the model or require a GPU.
