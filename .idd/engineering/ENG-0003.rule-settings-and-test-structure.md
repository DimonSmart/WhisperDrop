# ENG-0003.rule-settings-and-test-structure

## Rule

Persist user settings in a simple JSON document through a focused settings service. Keep the solution to one production application project and one test project unless an additional project provides clear practical value. Maintain a distinct Whisper integration test that can run against a locally available model without requiring that model in ordinary CI.

## Applicability

Conditional

## Applies when

- implementing or changing application settings persistence, project structure, or Whisper integration verification

## Rationale

The application is intentionally small; straightforward persistence and a minimal project structure keep its implementation proportionate. A real-runtime integration check provides evidence that local recognition works without imposing large model downloads on routine CI.

## Guidance

- Write settings atomically through a temporary file and replace or move operation.
- The Whisper integration test may be explicitly selected or skipped when a local model is unavailable; ordinary CI does not download large Whisper models.
- Keep build and test commands in `.idd/verification.yaml`, not in this rule.

## Verification

Settings persistence is implemented as a focused JSON-backed service with atomic replacement. The solution has a production application project and a test project unless another project has a clear practical justification. A distinct local-model Whisper integration check exists and routine CI does not download the model.
