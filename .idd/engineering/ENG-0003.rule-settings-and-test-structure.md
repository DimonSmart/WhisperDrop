# ENG-0003.rule-settings-and-test-structure

## Rule

Persist user settings in a simple JSON document through a focused settings service. Normalize newly introduced settings independently, keep transcription execution based on immutable snapshots, and keep the solution to one production application project plus one test project unless another project has clear practical value.

## Applicability

Conditional

## Applies when

- implementing or changing settings persistence, transcription options, project structure, or Whisper integration verification

## Rationale

WhisperDrop is intentionally small, but recognition settings can change while work is running. Atomic persistence plus snapshot semantics make behavior predictable without introducing a larger state-management framework. A real-runtime integration check provides evidence that local recognition works without imposing multi-gigabyte model downloads on routine CI.

## Guidance

- Write settings atomically through a temporary file and replace/move operation.
- Missing properties from older JSON receive defaults. Invalid enum/thread values normalize without discarding unrelated valid settings.
- Keep vocabulary/context as user text. Do not automatically generate, interpret, or rewrite it before persistence or recognition.
- A single transcription captures one recognition-options snapshot at start. `Transcribe all` captures one snapshot for the entire batch.
- Runtime-global device selection is not a mutable processor option: after native initialization a new device value is saved for next launch and surfaced as restart-required.
- The Whisper integration test may be explicitly selected or skipped when a local model is unavailable; ordinary CI does not download large Whisper models.
- VAD tests use a small resource or test doubles and must cover atomic success/failure/cancellation without requiring a recognition-model download.
- Runtime-selection tests must not force incompatible GPU backends on CI runners.
- Keep build and test commands in verification configuration rather than duplicating operational commands in this rule.

## Verification

Settings coverage establishes defaults, round-trip persistence, old-JSON loading, tolerant normalization, and atomic writes. Workspace coverage establishes single/batch snapshot semantics and translation-model validation. VAD download coverage establishes successful atomic finalization plus failure/cancellation cleanup. A distinct local-model Whisper integration check exists and routine CI does not download the model.
