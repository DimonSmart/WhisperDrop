# ENG-0002.rule-local-recognition-runtime

## Rule

Use the pinned `handy-computer/transcribe.cpp` C API and Parakeet Ultra Q8_0 GGUF for local recognition. Build and ship the native library and every required backend and dependent library app-local for each supported RID. Do not depend on the current working directory, an installed SDK or native runtime, or a command-line recognizer.

Initialize the selected native backends before loading the model. Keep the managed bindings aligned with the pinned C header and ABI; initialize public C structures through their native initialization functions. Own native model and session lifetimes deterministically, release every session before its model, and serialize recognition runs that share a model handle. Keep the abort callback and its state alive until the native run returns, and do not replace the callback during a run.

Pass mono float32 samples at 16 kHz with the exact sample count. Report success only when the native status is successful and the run was neither aborted nor truncated. Surface cancellation, truncation, repetition, backend failures, and other native errors as distinct outcomes. Expose only metadata the native API actually returns; do not present uncalibrated token scores as recognition confidence.

## Applicability

Conditional

## Applies when

Changing local recognition, native model loading, processing-device selection, or recognition-runtime packaging.

## Rationale

The native C API and its ABI are version-sensitive. Explicit ownership, serialized calls, and app-local backend resolution keep model use predictable across the supported desktop runtimes.

## Guidance

- Pin the upstream runtime commit, its native submodule commits, the C header, model revision, and required build configuration. Record model size and SHA-256 from the exact published bytes.
- Keep the model loaded across sequential queue items. Do not run concurrent native recognition calls against one model handle.
- Implement Auto, CPU, and GPU according to the backend actually available for each packaged RID. Auto may report CPU fallback; a forced GPU request must report an actionable error when its backend is unavailable.
- Keep native results and strings valid only for the duration guaranteed by the C API. Copy data into managed ownership before another mutating call or native release.
- Do not add model-specific decoder controls that the selected model ignores, artificial recognition progress, or a command-line process in the shipped product.

## Verification

Native ABI and lifetime coverage demonstrates compatible struct layout, callback lifetime, deterministic disposal, cancellation, and explicit partial-result/error handling. Packaged-runtime checks establish that the expected native library and backend load from the application bundle. Device checks establish the reported backend and CPU/GPU selection behavior on supported hardware.
