# ENG-0004.rule-release-and-updates

## Rule

Treat release versioning, packaging, update checking, and macOS installation as one coherent distribution contract: version comes from a Git tag; GitHub Release publishes verified artifacts; Homebrew metadata is derived from those artifacts; About/update code consumes only those published channels.

## Applicability

Conditional

## Applies when

- changing CI/CD, packaging, version metadata, release naming, Homebrew Cask publication, About version display, update checks, or application update behavior

## Rationale

Automatic update is safe only when application metadata, GitHub Release assets, Homebrew Cask metadata, and installed bundle verification agree on the same semantic version and artifact naming contract.

## Guidance

- Keep `vMAJOR.MINOR.PATCH` tags as the sole release version source.
- Do not publish release artifacts from ordinary branch CI.
- Verify package contents and version metadata before creating/updating a GitHub Release.
- Generate Homebrew Cask version and hashes from the already-published release/checksum set; do not duplicate release hashes manually.
- Keep GitHub HTTP, process execution, Homebrew logic, update-environment detection, and URI launching outside the About UI.
- Never run Homebrew through `sh -c`; pass executable and argument list directly.
- Do not modify/close the running application before Homebrew package publication and installed-version verification succeed.
- Once package modification starts, do not cancel the Homebrew process.
- Keep manual ZIP/debug/custom-path installations read-only from the updater's perspective.
- Any renaming of app bundle, GitHub asset pattern, Cask token, application ID, or Info.plist version field must be treated as a coordinated migration across workflow and updater code.

## Verification

Build CI runs on all supported development runner platforms. Update-service tests verify version and Homebrew semantics without invoking a real browser or brew command. Release and Homebrew workflow syntax and artifact-name contracts are reviewed together; end-to-end publication remains an explicit tag operation.
