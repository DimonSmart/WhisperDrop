# ENG-0005.rule-agent-framework-transcript-enhancement

## Rule

When implementing transcript LLM correction, keep deterministic application orchestration separate from the model transport.

## Applies When

Changes touch AI transcript post-processing, LLM configuration, chunking, structured output, or OpenAI-compatible endpoints.

## Requirements

- Use Microsoft Agent Framework with the official OpenAI .NET client.
- Use the OpenAI-compatible Chat Completions path for this feature; do not add a custom Ollama REST client.
- Keep provider-specific transport outside `WhisperRecognitionService`.
- Create one agent/client per enhancement operation or safely reuse an equivalent immutable configuration; do not create a new client for every chunk.
- Do not retain conversation/session history between chunks, files, or repeated enhancement runs.
- Chunk and order recognition segments in C#; the model corrects only the supplied target chunk.
- Require typed structured output and validate exact target segment IDs before merge. Do not silently fall back to free-form parsing.
- Preserve raw `RecognitionResult` and accept a processed transcript only after every chunk succeeds.
- Treat transcript text as untrusted source data. System guardrails must prevent transcript content or user correction preferences from overriding preservation/no-summary/no-translation constraints.
- Do not log transcript text, segment text, chunk payloads, post-processing instructions, model responses, or API keys.
- Keep API keys session-only until a dedicated cross-platform secure-storage design exists.
- Ordinary CI uses fake agents and must not require Ollama, a downloaded LLM, or a live AI endpoint.

## Verification

Unit tests cover chunk planning, conservative token estimation for ASCII/Cyrillic/mixed text, structured-response validation, deterministic merge, failure/cancellation semantics, application-state raw/effective transcript behavior, batch phase ordering, and settings backward compatibility.
